# 运维与验收清单（简体中文）

[English](operations.md) · **简体中文**

本文只讲日常运维：怎么验收、进程怎么活、怎么停怎么删。安装、配置项、agent 接入见 [README.zh-CN.md](../README.zh-CN.md)。

## 一、四个角色

| 角色 | 实体 | 什么时候活着 | 干什么 |
| --- | --- | --- | --- |
| 网页服务 | `postbox up` | 常驻（注册自启后开机隐藏运行） | 存文件、渲染手机页面、收反馈、接收手机上传、双向服务共享目录、定时清过期包 |
| 公网隧道 | `tools/cloudflared.exe` | 上一条的子进程，被它监督，挂了会退避重启 | 开一扇对外的门，发一个 `xxx.trycloudflare.com` 域名 |
| 推送 | ntfy.sh（公共服务器，不在你机器上） | 不需要常驻，调用系统 `curl` 发一条就走 | 有新文件时敲你手机一下 |
| MCP 服务 | `postbox mcp` | agent 客户端启动时拉起，客户端退出即消失 | 让 agent 用工具调用上面三件事 |

关键设计：**这四样东西互不通信，只通过 `data/` 目录交换信息**——没有 IPC、没有本地管理接口、进程之间没有 socket。

```
data/config.json           端口、监听地址、公网地址、ntfy 主题、访问密钥
data/bundles/<token>/      每个已发布的文件包：meta.json、files/、archive.zip
data/inbox/feedback.jsonl  手机提交的全部反馈（一行一条）
data/tmp/                  publish_text 落地文本、Word 内嵌图片抽取的临时目录
data/autostart.vbs         只有注册了 Windows 登录自启才会有
```

所以 MCP 进程不需要知道网页服务在不在、也不需要连它——它写完文件，网页服务自然就能服务；网页服务更新 `base_url`，MCP 下次读配置就拿到新域名。`up` 没在跑的时候发布照样成功，只是链接先是 `http://127.0.0.1:<端口>`，等服务起来才换成公网地址。

## 二、把哪个目录交给手机

服务一直跑着，这些命令随时敲，手机刷新一次页面就生效，**不用重启**。

### 共享目录 —— 手机 ⇄ 电脑（能翻、能下载、能往里传）

```bash
postbox share add D:\某个目录   # 开一个，可以反复加，最多 20 个
postbox share list             # 看开了哪几个，以及手机用哪个编号访问
postbox share rm 0             # 按编号收回
```

- 开了之后手机在首页「共享目录」那里能看到，也可以直接打开 `/s`。点进去能翻目录、下载、用和文件包
  一样的预览看文件（视频能拖、`.docx` 带着图、宽表格能左右滑），也能往任意一层小文件夹里传。
- 目录必须已经存在、必须是绝对路径。系统盘上的一律拒绝，`share add` 会直接告诉你原因。
- 名字以点开头的文件和文件夹永远不列出、也取不到；`..` 出不了你开的那个目录。
- 正在传的时候把目录收回，最后那一片会被拒，不会写进去。

### 上传目录 —— 手机 → 电脑（只进不出）

```bash
postbox upload add D:\某个目录
postbox upload list
postbox upload rm 0
```

只希望手机往里塞、不希望它翻的就用这个。同一个目录两样都开了，手机上只显示一条，标成共享目录那条。

### 传得慢或者传不上去的时候

1. 先量隧道，别先怀疑工具：

   ```bash
   curl -X POST --data-binary @一个200KB的文件 \
     "<公网地址>/api/upload?key=<访问密钥>&d=0&n=probe" -o /dev/null \
     -w "%{http_code} %{time_total}s %{speed_upload}B/s\n"
   ```

   这会在你开的目录里留下一个叫 `probe` 的文件，量完删掉。同一条免费隧道在同一台机器上既量到过
   1.5 MB/s，也掉到过 10 KB/s，所以传不动多半是隧道的事。
2. 超过 512 KB 会自动切成 512 KB 一片，一片一个请求。哪一片电脑没收到，就从电脑报回的位置续，
   所以大文件是「慢，但会到」。
3. 每个文件一行，各自有 暂停 / 继续 / 取消 / 重试，状态行写的是电脑确认收到的字节数，不是浏览器
   交出去的字节数。暂停是等当前这一片传完再停，所以点继续一定能从电脑确认过的位置接着发。底部那颗
   按钮在这一批没结束之前是点不动的 —— 这是故意的：以前连点两下，同一个文件就会从零再传一遍。
4. 手机上的进度条量的是浏览器交出去的字节，不是电脑收到的字节。判断成没成，看每个文件下面那行
   「已存到 …」。
5. 连着同一个 Wi-Fi 就别走隧道：`http://<电脑IP>:8712/upload`。同一台机器实测 1 MB 直连 0.036 秒、
   走隧道 115 秒。
6. 半截文件在哪：分块会话在 `data/tmp/up-<编号>.part`（24 小时后清），落进你选的那个目录里的
   `.part`，半小时没再被写过就会被扫掉。

## 三、验收清单

在手机上逐条确认：

- [ ] 关闭 agent 客户端，手机仍能打开之前推送的链接（证明服务不依赖客户端）
- [ ] 在文件包页面（`/b/<token>`）底部「写反馈」提交一句话，`data/inbox/feedback.jsonl` 里多一行，`postbox inbox` 能看到
- [ ] 这条反馈只出现在该文件包页面的「你在这个文件页提交过的意见」下面，别的地方看不到
- [ ] `/?key=访问密钥` 列出全部在有效期内的文件包和各自过期时间；密钥错或不填时出现的是输入密钥的表单，不是列表
- [ ] 同一页上「传到电脑上」「共享目录」排在文件包列表**前面**；包攒过 8 个之后多出来的收在「还有 N 个更早的」里（`?all=1` 展开）—— 这两个入口不该要靠往下翻才点得到
- [ ] 单个文件「下载原文件」可用；多文件包「打包下载全部」得到 zip 且能解压，中文文件名不乱码
- [ ] 图片 / PDF / 音视频在页内直接预览；`.md` 渲染成排版页面；`.docx` 连内嵌图片一起渲染；`.xlsx` 按工作表渲染
- [ ] 视频能拖进度条：`curl -sD - -o /dev/null -H 'Range: bytes=0-1023' http://127.0.0.1:<端口>/raw/<token>/<序号>` 回 `206` 且带 `content-range: bytes 0-1023/<文件大小>`；手机上不必等整段传完就能开播、能拖到中间
- [ ] 同一个包里的 `.mkv` 或 `.avi` 给的是说明和下载按钮，不是一个只能黑屏的播放器
- [ ] 手机上的宽表格是左右滑动而不是挤成一团
- [ ] 把链接发给别人，对方在没有你任何账号的情况下能打开（这就是交付能力）
- [ ] `postbox upload add D:\某个目录` 之后，手机打开 `/upload`：传一个小文件，它落到那个目录（或你现填的小文件夹）里，`postbox uploads` 能看到这条流水
- [ ] `postbox share add D:\library` 之后：`/s` 列出共享目录，`/s/<序号>` 能翻（目录在前、以点开头的项不出现），点开一个文件用的就是文件包那套预览（视频能拖、docx 图片能显示）
- [ ] 从共享目录页上的「传东西到这个文件夹」传进去的文件，确实落在那一层，刷新就能看到
- [ ] `postbox logs` 能看到隧道就绪和推送记录；重启后约 30 秒内手机收到「postbox 新地址」推送 —— 没收到时 `logs` 会写明推送是不是失败了、为什么
- [ ] 同一个文件名传两次得到 `名字 (1).ext`，电脑上原有那份没被顶掉
- [ ] `postbox upload add C:\anything` 被拒绝并说清楚为什么；一个还不存在的目录同样被拒绝
- [ ] 不带访问密钥时上传页回 401，`POST /api/upload` 也回 401
- [ ] 超过 512 KB 的文件会分成几片（每片 512 KB）到达并逐字节拼回原样；掐断其中一片后，是按电脑报回的 `received` 位置续传，不是从头再传
- [ ] 手机上点「提交反馈」真的能提交（页面 CSP 里要有 `connect-src 'self'`，缺了这行按钮点了没反应）
- [ ] 电脑重启后约 30 秒内，手机收到一条「postbox 新地址」推送，新域名可打开；**重启前生成的链接按设计全部失效**
- [ ] 过期（默认 30 天）的文件包自动消失，页面变成「链接不存在或已过期」
- [ ] `curl -sD - -o /dev/null https://<域名>/b/<token>` 能看到 `content-security-policy`、`x-content-type-options: nosniff`、`referrer-policy`
- [ ] 文件包页面和文件页的 HTML 里搜不到 `access_key`（这条有单元测试兜着）

## 四、生命周期对照

| 事件 | 影响 | 你要做什么 |
| --- | --- | --- |
| 重启 agent 客户端 | 只重启 MCP 进程，服务和隧道不动 | 无 |
| 重启电脑 | 服务与隧道重新拉起，**trycloudflare 域名会变** | 无，新域名自动推到手机 |
| 电脑睡眠 | 隧道断，手机打不开；推送照常但链接失效 | 把电脑设为不睡眠 |
| cloudflared 自己退出 | `up` 会在几秒后重启它并推送新域名 | 无；若反复重启，检查 `postbox config cloudflared get` 和网络 |
| `up` 退出 | 页面打不开；MCP 照样往 `data/` 里发布 | 再跑一次 `postbox up`，或等登录自启 |
| 改 `port` / `bind` / `tunnel` | 正在跑的服务仍用旧值 | 重启 `postbox up` |
| 改 `access_key` / `ntfy_topic` | 不用重启，服务会重新读配置文件 | 换了主题手机要重新订阅 |
| `upload add` / `upload rm` / `share add` / `share rm` 一个目录，或改 `upload_max_mb` | 不用重启就生效；目录清空后首页连入口都不显示 | 无 |
| 上传进行到一半时把那个目录收回 | 最后一片会被拒，什么都不写 | 重新打开页面再传一次 |
| 上传中途断了 | 分块会话在 `data/tmp/up-<id>.part`，超过一天由例行清理收掉；落进你选的那个目录里的 `.part`，半小时没再被写过就扫掉 | 重传那个文件即可，新会话从零开始 |
| `data/config.json` 丢了 | 除 `init` 外的命令都会拒绝运行，重建后是全新的密钥和主题 | 手机重新订阅；旧文件包链接仍然能打开（token 存在 `bundles/` 里） |

## 五、停止与卸载

临时停（保留全部配置和数据）。按 PID 停**这个项目**的进程：

```powershell
# 哪个是网页服务？它的 CommandLine 以 " up" 结尾
Get-CimInstance Win32_Process -Filter "Name='postbox.exe'" | Select-Object ProcessId, CommandLine

Stop-Process -Id <pid> -Force        # cloudflared 是它的子进程，会一起被收掉
```

只停 `up` 就够了：`cloudflared` 是它拉起的子进程，父进程一没它就跟着走；在它窗口里按
Ctrl+C 干净退出同样会停掉隧道。

**不要按进程名杀。** `taskkill /IM cloudflared.exe /F` 会把这台机器上所有 cloudflared 一起
带走，包括别的项目的隧道；`taskkill /IM postbox.exe /F` 还会顺手结束 agent 客户端持有的 MCP
进程。确实要单独挑出某条隧道时，先列 `Name='cloudflared.exe'` 的进程，拿命令行里的
`--url http://127.0.0.1:<端口>` 和 `postbox config port get` 对一遍，再停那个 PID。

取消开机自启：

```bat
postbox autostart uninstall    :: 删计划任务或 HKCU\...\Run 项 + data/autostart.vbs
```

彻底卸载（按顺序）：

1. 在 agent 客户端的 MCP 配置里删掉 `postbox` 那一项
2. `postbox autostart uninstall`
3. 按上面说的方法，用 PID 停掉 `postbox up`
4. 删除整个项目目录（`data/` 里的文件包和反馈一并没了；想留反馈先拷走 `data/inbox/feedback.jsonl`）
5. 手机 ntfy 里取消订阅你的主题

这套东西**没有装任何系统服务、没有驱动、没有后台更新器**，cloudflared 和 ntfy 都不需要注册账号，删目录即净。

## 六、故障排查

| 现象 | 先查 | 处理 |
| --- | --- | --- |
| 手机收不到推送 | `postbox config ntfy_topic get` 看主题是否为空；手机是否订阅了同一个主题；系统里有没有 `curl` | 订阅后跑 `postbox notify-test` |
| 链接打开是「链接不存在或已过期」 | 是不是上一次 `up` 重启之前生成的？包过期了吗？发布用的客户端 `--root` 是不是别的目录？ | 在跑着服务的那台电脑、那个目录里重新发布 |
| 发布成功但链接指向 `127.0.0.1` | `postbox config base_url get` 是 `(none)`，说明隧道还没报出域名 | 检查 cloudflared 路径和网络；`up` 打印「隧道就绪」才算通了 |
| 两个客户端只有一个能从手机打开 | 它们的 `--root` 不同，等于两套互不相干的实例（两套密钥、两个主题） | 把每个客户端的 MCP 配置都指向同一个 `data/` 目录 |
| Word 预览一片空白 | 老版 `.doc`（Word 97-2003）不支持；超过 20MB 的文档不做在线预览 | 下载原文件用 Office/WPS 打开 |
| 手机上点「提交反馈」没反应 | 页面 CSP 少了 `connect-src 'self'`，`curl -sD -` 看一眼响应头 | 用当前 `master` 重新编译——0.2.0 就是缺了这行 |
| 上传页里一个目录都没有 | `upload_dirs` 是空的 | `postbox upload add D:\某个目录` |
| 上传跑到 100~170 秒被 502/524 掐断 | 那是隧道的请求时限，不是 `upload_max_mb`。隧道上行本身能差几个数量级（这台机器既量到过 1.5 MB/s，也量到过 10 KB/s），先拿一个 200 KB 的请求看当前速度；超过 512 KB 本来就该走切片，整文件失败说明手机上是旧页面，刷新一次 | 特别大的文件还是同一 Wi-Fi / Tailscale；要让手机能反向取东西就 `postbox share add` |
| 上传说目录不存在 | 电脑上那个目录被改名或删了 | `postbox upload list` 会标出来，重新 add 或收回 |
| 共享目录回 401 | `/s`、`/sf`、`/sd`、`/sh`、`/sm` 全都要密钥，浏览器得带上 Cookie 或在地址里加 `?key=` | 先打开一次 `/?key=…`，或者给链接补上 `?key=…` |
| 共享列表里找不到某个文件 | 它的名字以点开开头，或者那个目录超过 500 项 | 设计如此；改个名字或者往深处翻 |
| 重启后手机没收到「新地址」推送 | `postbox logs` 会写推送有没有失败、为什么（curl 找不到、主题为空、ntfy 拒绝） | 按原因修；`postbox notify-test` 重测一次链路 |
| Word 文字有了但图片没有 | 图片解在 `data/tmp/m-<token>-<idx>/`，文件包过期时会被一起删掉 | 重新发布一次 |
| `cargo build` 报「拒绝访问（os error 5）」 | exe 正在被服务或某个 MCP 进程占用 | 先结束对应进程，或换 `--target-dir` |
| 首页地址或密钥忘了 | `postbox token` | 打印 `<公网地址>/?key=<访问密钥>` |
| 端口被占用起不来 | `postbox config port get` | `postbox config port 8899`，然后重启 `up` |
| 页面在手机上排版怪 | `postbox --version` 和你构建用的 commit | 截个图，开个 issue |

## 七、磁盘上都有什么、会长多大

* `data/bundles/<token>/files/` 里放的是发布文件的**副本**，所以这个目录随发随长。到期删除是唯一的回收机制：默认 30 天，`--days 0` 永久保留，每小时和每次发布时各扫一遍。
* `data/inbox/feedback.jsonl` 上限 4 MB，超了就把最旧的一半丢掉（最少保留 1000 条）。反馈历史要留就自己备份。
* `data/tmp/` 放 `publish_text` 的草稿和 Word 抽取的图片。普通条目超过 24 小时清掉；预览图片跟着它的文件包一起活、一起死。
* `data/config.json` 里有访问密钥。把它当 SSH 私钥看待：不进仓库、不放同步盘。

## 八、目前明确的不足

本地端口没有 HTTPS（TLS 到隧道为止）；文件包不能单独设密码；手机上传单文件卡在 100 MB（那是 Cloudflare 免费计划的请求体上限）；除 Cloudflare 那边之外没有访问日志；免费隧道不保证可用性且每次重启换域名；网页界面和命令行输出只有中文。浏览器自己解不了的编码（Firefox 上的 HEVC、任何浏览器上的 `.mkv`/`.avi`）仍然走下载，页面会说明原因而不是摆一个黑屏播放器。这些都写在 README 的「已知限制」里，也都欢迎有人提 PR。
